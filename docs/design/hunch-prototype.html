How a round works
  1. Call itChoose Up or Down. When our server accepts it, it records the current BTC/USD price as your entry.
  2. Wait at least 60 secondsPrice moves during this first minute don't settle the round.
  3. CompareHigher than entry means Up wins, lower means Down wins. Right is +1, wrong is −1.

At least 60 seconds after your prediction, we compare the latest available price with your entry price. If unchanged, we keep waiting.

If our price source has a problem, your round waits for valid data. An outage never counts as a loss. Results use exact prices, not rounded display values. You can close this page; your round keeps running and the result is here when you return.

Points only. No real money, deposits, purchases or prizes. Hunch is a game, not an exchange.

Prototype vs production
  • Prices. Seeded random walk, 1 quote/s. Production: Coinbase Exchange public BTC-USD, fetched server-side.
  • Server. In-page mock with fixed latency. Production: HTTP API with focused functions, state in a database.
  • Waiting and resolution. Mock checks once per sim second after the deadline. Production: a durable workflow waits 60s, then retries until a valid, differing quote exists.
  • Player credentials. Kept in a fake in-memory store so resets are clean. Production: browser storage holds the anonymous credentials; the server holds score and history.
  • Polling. Price every 2s, player state every 3s, every 1s once the minimum wait ends. Production: TanStack Query refetch intervals with the same shape.
  • Clock. Sim time can be sped up or skipped. Production uses server timestamps; the countdown is a client estimate only.
